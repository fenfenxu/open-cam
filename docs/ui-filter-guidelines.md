# 筛选与横向选择控件规范

## 核心原则

用户在控件关闭、已经选中值之后，仍然必须知道这个值属于哪个字段。不能让用户依赖回忆控件在打开前的位置，也不能只显示内部值、编号或短词。

## 两种允许的模式

### 1. 控件自身带字段名

用于工具栏、表格上方、横向表单等没有持续 Label 的场景。触发器始终显示：

`字段名：选中值`

例如：

- `摄像头：[1] 演示摄像头`
- `类型：徘徊逗留`
- `状态：已确认`
- `VLM 判定：误报`

代码统一使用 `web/src/components/app/labeled-select.tsx` 的 `LabeledSelect`，不要在页面里重新拼一套显示文案。

### 2. 外置持久 Label

用于设置表单、规则表单等纵向布局。Label 必须与 Select 直接相邻并保持可见，例如“模型来源”在下拉框上方。选中值本身可以不重复字段名。

## 文案与布局要求

- “全部”要和字段绑定表达：使用“全部摄像头 / 全部类型 / 全部状态”，不要显示 `__all__` 等内部哨兵值。
- 摄像头值保留 `[编号] 名称`，便于多路摄像头区分。
- 选中值过长时截断，但字段名不能被截断；控件允许换行，不能把筛选条撑出视口。
- 同一筛选条的控件高度、边框、圆角和下拉样式保持一致；优先通过公共组件调整，不在页面内单独覆盖。
- 复选筛选使用直接可执行的短句（如“仅看关注”“含观察记录”），不需要再包一层含义不明的“筛选”标题。
- 每个筛选条都提供固定位置的“重置筛选”按钮；无条件时保留可见但禁用，有任意条件时启用，并一次恢复全部默认条件。

## 本次巡检结论

- 事件页顶部四个筛选已统一为“字段名：选中值”。
- 设置页通知渠道、员工路由中横向摆放的摄像头 / 类型 / 渠道选择也按同一规则处理。
- 规则、模型、摄像头、训练页的 Select 已有外置 Label，继续使用外置 Label 模式。
