# 自助模型训练产品方案

> 目标：让非技术用户（店主）用一句自然语言描述需求，平台自动完成
> 标注、训练、评估、部署，产出可实时运行的定制小模型。
> 大模型的两个角色：**代替人标注**（生成训练数据）、**帮人操作平台**
> （语义解构 + 流程引导）。最终部署的始终是本地小模型，大模型只出现在
> 训练侧的一次性环节。

## 用户旅程（主线七步）

1. **说需求**：用户输入语义化目标，如"垃圾桶快满了就提醒我"。
2. **确认定义**：大模型把目标解构成结构化任务定义（见下节），
   并给出边界样本图让用户点"算/不算"，确认判定标准。
3. **选视频源**：选择已有摄像头或上传视频，平台自动抽帧。
4. **自动标注**：开放词汇检测出候选框 → VLM 打属性标签 →
   高置信样本直接入数据集，低置信样本交人工点选确认。
5. **训练**：从预训练 YOLO 微调，产出 `best.pt`。
6. **评估报告**：用一句人话 + 三个指标汇报
   （准确率 / 召回率 / 误报率），附典型对错样本图。
7. **一键部署**：达标则替换线上模型，不达标则引导补充样本重训。
   旧模型保留，随时一键回滚。

## 语义目标的结构化解构

大模型把自然语言转成一份任务定义（用户确认后才进入下一步）：

```json
{
  "object": "垃圾桶",
  "property": "满溢状态",
  "classes": ["空/正常", "将满", "满溢"],
  "rule": {"type": "state_alert", "trigger": "满溢 持续 5 分钟"},
  "metrics": {"accuracy": 0.90, "recall": 0.85, "false_alarm_per_day": 2}
}
```

解构要点：

- **对象与属性分离**：认什么（垃圾桶）× 判断什么状态（满溢）。
- **类别必须封闭**：大模型主动提出 2–4 个互斥类别，让用户确认，
  避免训练目标含糊。
- **指标给默认值并解释**：如"召回率 85% 意味着大约每 7 次满溢会
  漏报 1 次"，用户只调不调参，只看懂后果。
- **边界样本确认**：从抽帧里挑 5–10 张模糊样本（半满、被遮挡），
  让用户点"算不算"，这些样本直接进数据集，同时校准判定口径。

## 自动标注流水线

核心思路：不让用户画框，只做选择题。

1. **出框**：用开放词汇检测模型（YOLO-World / YOLOE，接受文本提示），
   拿解构出的对象名（"垃圾桶"）直接在抽帧上出候选框——
   这是"语义目标 → 检测框"的桥，用户零操作。
2. **打标**：VLM（复用现有 moonshot VLM 配置）逐框判断属性类别
   （满/空），同时输出置信度。
3. **分流**：高置信直接入数据集；低置信进入"人工确认队列"——
   用户看到的是一张张裁好的小图，只需点"满/空/跳过"。
   预计每个场景人工确认 50–100 张，十几分钟完成。

## 大模型的两个角色小结

| 角色 | 环节 | 成本特征 |
|---|---|---|
| 标注员 | 出框（YOLO-World）+ 打标（VLM） | 一次性，几百张图，几元到几十元 |
| 操作助手 | 语义解构、指标解释、报告生成、不达标时的补救建议 | 每次训练几轮对话，可忽略 |

## VLM 选型（原则：可用、便宜、本地可低门槛）

VLM 配置走 OpenAI 兼容协议（`vlm_base_url` / `vlm_model` / `vlm_timeout` +
`OPENCAM_VLM_API_KEY`），以下选项均可直接换入。**标注（训练侧）与复核
（运行侧）允许配置不同的模型**：复核求快求省，标注求质量，任务级可覆盖
全局配置。

| 档位 | 模型 | 成本 | 适用 |
|---|---|---|---|
| 云端·默认 | 智谱 GLM-4V-Flash（OpenAI 兼容端点） | **免费**（限 1 并发） | 事件复核、小规模标注，零成本起步 |
| 云端·加强 | 阿里百炼 qwen-vl-max / Qwen3-VL-Flash | max 约 ¥3/百万输入 token；Flash 更低 | 大批量标注、疑难样本打标 |
| 本地部署 | Qwen2.5-VL-3B（Ollama/vLLM，4bit） | 一次性硬件，4–8GB 显存即可；Apple Silicon 8GB 统一内存可跑 | 本机或内网部署 VLM |

选型要点：

- **默认推荐 GLM-4V-Flash**：免费 + OpenAI 兼容，复核和 MVP 期标注
  够用；1 并发对标注流水线只是慢一点（串行打标几百张约十几分钟）。
- **本地部署选 Qwen2.5-VL-3B**：4bit 量化后 4–8GB 显存可跑，
  中文场景好；避免选 7B+（需 16GB+，超出门店普通机器）。
- **超轻量模型（SmolVLM2 等 2B 级）暂不作为默认**：中文理解弱，
  只作为极端低配硬件的备选。

## 模块划分（对应 open-cam 架构）

- `opencam/training/`：任务定义、抽帧、标注流水线、训练执行、评估。
- API：`POST /api/training/tasks`（创建任务，语义目标入参）、
  `GET /api/training/tasks/{id}/review`（人工确认队列）、
  `POST /api/training/tasks/{id}/train`、`POST /api/models/{id}/deploy|rollback`。
- Web：新增"模型训练"页，按七步旅程做向导式界面；
  模型管理（版本、指标、部署/回滚）挂在摄像头详情下。
- 模型产物与数据集存 `data/training/<task_id>/`，不进 git。

## 关键决策

- **第一期只做"固定区域 + 状态分类"**（垃圾桶满溢、工服合规）：
  对象位置固定，框由用户画一次区域即可，训练目标退化为分类问题，
  难度和数据量都最低，最容易跑通全流程。
- **第二期上开放词汇出框**，支持对象位置不固定的场景（桌面遗留）。
- **训练先本地**：M 系列芯片微调 yolov8n 分类/检测可接受；
  云端训练 API 作为后续选项，接口预留。
- **误报反馈是飞轮**：事件页加"误报/漏报"按钮，反馈样本自动归入
  对应任务的数据集——独立于自助训练也值得先做，系统越用越准。

## 分期 Roadmap

| 期 | 内容 | 验收 |
|---|---|---|
| MVP | 固定区域状态分类：垃圾桶满溢端到端跑通七步 | 店主无协助完成一次训练，指标达标并部署 |
| 二期 | 开放词汇出框 + 检测微调（桌面遗留）；误报反馈飞轮 | 非固定对象场景可训练 |
| 三期 | 云端训练选项；多摄像头样本合并；跨店预置行业模型 | 新场景冷启动只需确认少量样本 |

## 风险与对策

- **VLM 标注质量不稳**：低置信分流 + 人工确认兜底；
  评估集必须含人工标注样本，不接受全自动评估。
- **用户训出更差的模型**：部署前与线上模型 A/B 对比，
  只在指标全面更优时建议替换；回滚入口常驻。
- **样本不足**：抽帧时按多样性去重（感知哈希），
  不足时明确提示"再拍 N 分钟不同时段的画面"。
