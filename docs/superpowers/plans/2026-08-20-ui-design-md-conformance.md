# open-cam 前端 design.md 一致性修复计划

## 目标

按照仓库根目录 design.md，把当前 web/ 控制台中已经发现的页面和公共组件不一致问题收敛到统一实现，重点解决：

- 筛选、步骤条、表格、状态徽标、表单、抽屉和危险操作的统一选型；
- 键盘、焦点、Label 关联和错误反馈等可访问性问题；
- 页面私有视觉样式、直接颜色和状态枚举泄漏；
- 步骤流程可绕过前置条件的问题。

本计划以 design.md 为唯一验收依据，不重新定义设计规范。

## 范围

### 包含

- web/src/components/app 和 web/src/components/ui 的公共能力补齐；
- web/src/views 下现有仪表盘、事件、摄像头、规则、模型、训练、方案市场、设置和详情页面；
- 对应 Vitest 测试、无障碍行为测试和必要的 design.md 落地说明；
- 当前实现与 design.md token 不一致的 CSS/组件收敛。

### 不包含

- 后端 API、数据库、模型推理和业务规则逻辑；
- 重新设计品牌视觉或新增页面；
- 不相关的训练测试、热加载改动和工作树中的其他用户修改；
- 修改生产配置、环境变量或直接推送 main。

## 分阶段拆解

### 阶段 1：公共交互基础

1. 将 DataTable 的可点击行补成键盘可访问的交互，并保证行内按钮不会重复触发行点击。
2. 抽取统一的危险操作确认 Dialog，覆盖删除、卸载、清 Key、回滚和强制部署。
3. 统一状态徽标和枚举映射，拆分事件处置状态、VLM 处理状态、VLM 判定、摄像头状态和训练状态。
4. 补齐表单字段的 Label 与控件 id 关联；明确 LabeledSelect 只用于列表筛选，表单使用 Select + Label。
5. 为查询错误提供页面内联错误、重试或修正路径，不能只用 Toast 或退化为空列表。

### 阶段 2：页面行为收敛

1. 提取公共 StepProgress，规则页和训练页统一使用 nav、ol、li、aria-current="step" 和前置条件。
2. 修复训练流程跳步：只有完成当前步骤的必要条件后，才能进入下一步；返回不会使用 destructive。
3. 修复事件列表的整行键盘打开、关注按钮 aria-label/aria-pressed 和 VLM 状态/判定分层。
4. 修复摄像头、规则、方案市场、设置、模型和训练页面的危险操作、表单标签、错误态和状态展示。

### 阶段 3：视觉 token 与响应式收敛

1. 对齐 design.md 与实际 CSS/组件 token，特别是 muted foreground、Button destructive、筛选控件高度和 DetailDrawer 内边距。
2. 将客流图、规则画布、开发提示等直接颜色整理为语义 token；媒体黑底作为明确的媒体容器例外。
3. 统一卡片圆角、阴影、间距和状态颜色；检查 AppShell、筛选栏、步骤条、表格和抽屉在窄屏下不溢出。
4. 补充代表性页面的视觉回归检查和无障碍测试。

## 验收标准

### 组件和交互

- 所有列表可点击行都能通过键盘打开，且行内按钮不会重复打开详情。
- 所有删除、卸载、清除、回滚、强制部署等危险操作都有标题、后果说明、取消和确认动作。
- 所有表单控件都有可见中文 Label，并通过 htmlFor/id 或等价语义关联。
- 事件筛选继续使用 LabeledSelect，选中值包含字段名，并保留可见“重置筛选”。
- 规则和训练步骤使用同一公共步骤条；未满足前置条件不能跳步。
- 事件表格不再把 VLM 处理状态和 VLM 判定混为同一状态。

### 状态、反馈和视觉

- 后端枚举不直接泄漏到用户界面；未知值显示统一中文兜底。
- 查询失败显示内联错误和可执行的重试/修正动作，不会误显示为空数据。
- 页面颜色、圆角、阴影、控件高度和间距使用 design.md / index.css 的语义 token。
- 关键页面在桌面、窄屏和键盘操作下无明显溢出或不可操作控件。

### 验证

- 相关 Vitest 全部通过；
- web TypeScript 检查通过；
- design.md 官方 linter 无 error/warning；
- git diff --check 通过；
- 交付说明列出验证命令、未覆盖的视觉范围和例外记录。

## 交付约束

- 每个阶段通过独立子任务和 PR 交付，PR 标题和正文包含主任务编号；
- 不直接修改 main，不覆盖工作树中与本计划无关的用户改动；
- 新增公共组件前必须确认现有组件无法承载，并同步更新测试与 design.md；
- 如果某项需求无法在当前阶段安全完成，在对应任务中记录 blocked_reason，不用临时页面私有实现绕过规范。
